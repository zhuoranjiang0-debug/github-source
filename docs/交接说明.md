## 二、这个项目现在到哪一步

- **已经做完并实测通过**：数据层、运行器、编辑器（拖拽/属性/撤销/存读）、
  逻辑编辑器（当…如果…就…）、移动端（横屏平板 + 屏幕按键）、AI 助手第一块
  （离线生成敌人与"天上掉金币"规则）
- **定位**：只做**横版动作 / 平台跳跃类**原型；别的风格怎么加写在
  [ROADMAP](ROADMAP.md) 的「扩展位」一节
- **下一步候选**：属性清单（[设计稿已写好，待评审](属性清单-设计稿.md)）、
  素材系统、AI 助手后续两块、分享功能

一句话标准：**用这个工具，不写一行代码，能做出一个能跑、能装在平板上玩的原型。**
这条已经达成。

## 三、项目是怎么组织的（一页说清）

```
一份 .ai2d.json（游戏原型）
   │
   ├── 数据层 core/model   —— JSON 的"语法规则"：工程 / 实体 / 场景 / 规则 / 词汇表
   ├── 编辑器 editor       —— 改这份 JSON：画布、属性面板、逻辑编辑器、AI 面板
   └── 运行器 runtime      —— 把这份 JSON 变成能玩的游戏：物理、碰撞、规则引擎
```

**三条关键约定**（它们解释了这个项目为什么长这样）：

1. **一个游戏 = 一份 JSON。** 保存、加载、撤销、分享、AI 产出，全都退化成"处理 JSON"。
2. **逻辑用「事件—条件—动作」三段式**，而且**词汇表是数据**：所有事件/条件/动作
   声明在一个文件里，编辑器表单和句子都从它生成。**加一种动作只改一个文件。**
3. **界面上的说法必须是用户的话**：不写 `ui_accept` 写「跳跃」，不写 `collision_group`
   写「碰撞：地面」，规则配完要能**念成一句中文**读回来给人检查。

## 四、交接时要给的东西（清单）

### 文件

| 给什么 | 怎么给 | 注意 |
| --- | --- | --- |
| 整个仓库 | 推荐用 git（clone 或私有仓库），保留提交历史 | 历史里有每个决定的"为什么" |
| `Godot_v4.6.1-stable_win64.exe` | 单独给（165 MB，不入库） | 或按 README 里的链接自己下载**同版本** |
| `app/export_presets.cfg` | **单独私发** | 它被 `.gitignore` 挡住了（里面有签名口令），但没有它**打不出安卓包** |
| `项目计划书.doc`（根目录） | 单独给 | 学校材料，保留本地，不随公开源码分发；旧 Git 历史中仍有该文件 |
| 安卓工具链（可选） | 桌面 `android-tools`（JDK + SDK + 调试签名） | 只有要重新打包安卓才需要 |

### 非文件（同样重要，容易漏）

- **当前优先级**：顺利结题第一；每 1~2 周要有一个能演示的东西
- **进度**：M0~M3、M6、M4 第一块已完成；属性清单是下一个候选
- **导师那边**：中期检查日期、结题材料清单**还没拿到**，拿到后材料优先
- **演示现场**：笔记本 + 借来的安卓平板
- **和用户的工作方式**：他不是程序员 —— 交付时必须给截图，让他按
  [测试清单](测试清单.md) 验收；有决定就写进 [决策记录](决策记录.md)

## 五、接手的第一个人物建议

按这个顺序做，每一小步都有正反馈：

1. 双击 `运行测试.bat`，看到 533 项全绿
2. 双击 `打开编辑器.bat`，点一下素材栏里的「金币」，改个颜色，按 `F5` 玩一下
3. 读 [决策记录](决策记录.md) 的**最后 10 条**（最近的决策最相关）
4. 按 [测试清单](测试清单.md) 走一遍 A~C 段（打开、画布、放置）
5. 想改代码时，从 `app/src/core/model/rule_vocabulary.gd` 或
   `app/src/runtime/rule_engine.gd` 开始 —— 这两个是核心，读懂它们就懂了项目

## 六、给接手的 AI 助手

仓库根目录的 **[AGENTS.md](../AGENTS.md)** 就是给它写的：命令、硬规矩、
已知的坑、常见任务改哪儿。**让它先读那一份**，别让它自己摸索。

里面最要紧的三条：

1. 改完**必须跑测试**并给用户**截图**
2. **改数据含义必须加版本号 + 写升级**（漏过升级，用户当场撞上 bug）
3. **新增能力只准"加"、不准"改语义"**

## 七、接到手之后可以先不管的事

- 架构够用，不需要重写。想重构先看 [决策记录](决策记录.md) 里的理由
- 有几个已知的、**故意没做**的小毛病（比如偶发"跳得特别高"），
  都记在 [测试清单](测试清单.md) 的「已知的粗糙处」，别当成 bug 追
- 属性清单这件事**先评审设计稿再动代码** —— 它改的是数据结构，牵一发动全身
