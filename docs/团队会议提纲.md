# 团队会议提纲

> 用法：带着这份提纲去开会，逐条过一遍，散会前把结论带回来。
> 这不是要填的作业，是需要团队**共同拍板**的问题清单。

## 一、用一句话说清我们在做什么

面向不会编程的游戏爱好者，做一个手机上的 2D 游戏原型创作工具——拖拖拽拽、AI 帮忙，十几分钟就能把一个点子变成能玩、能发给朋友的东西。

## 二、老实说，我们手上现在有什么

**只有产品的下半截。**

| 部分 | 状态 | 说明 |
| --- | --- | --- |
| 运行器 | ✅ 已完成并验证 | 给它一份描述游戏的 JSON，它就能把游戏跑起来 |
| 编辑器 | ❌ 一行都没有 | 用户实际拖拽操作的界面 |
| AI 助手 | ❌ 未开始 | |
| 打包手机 App | ❌ 未开始 | |

运行器已经能跑通一个完整的平台跳跃游戏：跳跃、吃金币加分、碰到陷阱扣血、集齐获胜、血量归零失败。

但用户还不能自己创作，因为编辑器没做。

**换句话说：发动机造好了，方向盘还没装。**

这件事必须在会上讲清楚，避免有人以为"项目快做完了"。

## 三、明天需要拍板的五件事

### 1. 目标定到哪一档

三个档位，代价完全不同：

| 档位 | 要投入的 | 说明 |
| --- | --- | --- |
| 结题够用 | 最小 | 一个能演示的闭环 + 文档。编辑器能拖、能跑、能存就够 |
| 做出能用的工具 | 大 | 加 AI 助手、分享、手机打包、真机测试 |
| 做成真产品 | 很大 | 远超一个学生项目的时间预算 |

我的建议是第一档，做到之后再视情况往上加。**先活到结题，再谈梦想。**

### 2. 代码谁来写（最重要的一条）

现在这套代码是 AI 写的。队里会写代码的那位同学，情况有两种：

- **他愿意接手**：那我们有一位能讲清楚原理的人，这套代码是资产。答辩时老师问"你们的逻辑引擎怎么设计的"，他能答。
- **他不接手也不参与**：那它就是个黑盒。能演示，但原理没人讲得清，答辩有风险。

请在会上直接问清楚：他愿不愿意投入，能投入多少。

### 3. 每人每周实际能投入多少时间

计划书上写的是每周 1~2 天。请每个人给一个**诚实的数字**，宁少勿多。

排期是按真实时间算的，一个人虚报，整个计划就废了。

### 4. 硬性时间节点

中期检查是什么时候？结题是什么时候？材料有什么格式要求？

**这个必须去问指导老师，不能猜。** 有了日期才能倒排计划，没有日期就只能凭感觉走。

### 5. 谁负责材料

结题报告、答辩 PPT、技术开发文档、用户操作手册——这些活儿的工作量不比写代码小，而且必须有人**专门盯**。

不要留到最后一刻临时凑。建议现在就指定一个人负责。

## 四、明天不用解决的问题

- 用不用 Godot —— 已经定了，不用再讨论
- 具体做哪些功能 —— 等目标和时间确定后再排
- AI 接哪家服务商 —— 不急，架构上已经留好了位置

## 五、散会后请带回给我的五条信息

1. 目标定在哪一档
2. 代码谁写、那位同学投入多少
3. 每个人每周的实际时间
4. 中期检查和结题的具体日期
5. 材料分工

把这五条发我，我来排下一步的具体计划。
