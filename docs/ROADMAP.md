# 路线图

按「垂直切片」推进：每个里程碑结束时，都必须有一个**能演示**的完整功能，而不是若干个各完成一半的功能。

## M0 基础层 ✅

- 数据模型与 JSON 序列化
- 语义校验（引用完整性、词汇表白名单）
- 示例工程与自动化测试骨架

**验收**：双击 `运行测试.bat` 全绿。

## M1 运行器 ✅

- 从 JSON 构建场景树
- 物理：重力、落地、碰撞
- 事件—条件—动作规则引擎
- 胜负结算、场景切换、对象生成与销毁

**验收**：示例工程「跳跃小恐龙」可玩——能跳、能吃金币、会受伤、能赢能输。

## M2 编辑器核心 🚧 最小闭环已完成

这是整个项目工作量最大的一块，也是决定产品成败的地方。

**已完成（能拖、能跑、能存）**

- 画布：缩放、平移、选中、拖动
- 底部素材栏：把对象拖到画布上放置
- 右侧属性面板：改颜色、位置、大小、自定义数值
- 撤销 / 重做（快照式，上限 50 步）
- 打开工程、保存工程
- 编辑与试玩共用同一份数据 —— 改完不用存盘，按 F5 就能看到

**还差**

- 缩放控制点与旋转
- 新建工程、另存为
- **增删规则**（事件 / 条件 / 动作）—— 归在 M3，是达成下面这条验收的最后一环

**验收**：在编辑器里从零做出一个能跑的平台关卡，全程不碰 JSON。
→ 摆放对象、调颜色尺寸、调数值、存盘都已经可以全程不碰 JSON；
**只剩"加一条规则"还得手改 JSON**，这一步在 M3。

## M3 逻辑编辑器 ✅

- 规则清单：每条规则都念成一句人话，一眼能读完整个游戏的逻辑
- 规则详情：用「当……如果……就……」三段式配置
- 事件 / 条件 / 动作的表单**由词汇表自动生成**，新增动作不用改界面代码
- 对象选择器：从工程里真实存在的标签和实例中下拉选择
- 每条规则都能被复述成一句中文，配完能读回来检查

**验收**：不写 JSON 就能做出「碰到敌人扣血、血量归零失败」这类逻辑。→ **达成**

**一句话验收**：打开逻辑编辑器，左边能读懂这个游戏怎么运作，右边能改。

## M4 AI 助手

> 为什么这块排在最前面：计划书标题里「AI 赋能」四个字，到这里为止一个都还没兑现。
> 它也是评审最容易问的地方。

**做法：接口先定，模型后接。**

```
AIService          统一入口：要什么、给什么，都用这一套说法
├─ MockProvider    离线、确定性、不联网、不花钱（答辩现场断网也能演）
└─ RemoteProvider  以后接真实模型（需要有 key 和网络，先只留位置）
```

三条铁律：

1. **AI 只产出数据，不直接改工程。** 产出的是 JSON（实体定义、规则草稿），
   改不改由人点「应用」决定。人永远是最后拍板的那个。
2. **产出必须过校验器。** 不合法的直接拒绝并说明原因——复用已有的
   `ProjectValidator`。这也是答辩时的加分点：AI 生成的东西同样要验证。
3. **一步可撤销。** AI 应用的结果和手改一样进撤销栈，`Ctrl+Z` 能撤掉。

**分四小块，每块都能单独演示：**

| 块 | 做什么 | 做完能演示什么 | 状态 |
| --- | --- | --- | --- |
| M4-a | AI 服务层 + 离线生成器 + 界面上「✨ 帮我做一个」入口 | 点一下，面板给出一份草稿，可以点「应用」或「算了」 | ✅ 完成 |
| M4-b | 一句话生成**一个敌人**（颜色、大小、形状、标签） | 画布上立刻多出一个紫色飞行小怪，能拖、能改、能撤，碰到会扣血 | ✅ 完成 |
| M4-c | 一句话生成**规则草稿**（"每 2 秒天上掉一个金币"） | 说一句话，规则配好，并且念回来给你看 | 未开始 |
| M4-d | 生成**配色变体**（森林 / 夜晚 / 沙漠…） | 一句话把整关配色换掉 | 未开始 |

**M4-a / M4-b 已完成**（2026-09-20），现在会做两件事：
「一个会飞的紫色小怪」→ 生成一种敌人并摆进关卡；
「每 2 秒掉一个金币」→ 生成一条定时掉金币的规则。
两件事都走同一套流程：**草稿预览 → 人能看懂它要做什么 → 过校验 → 一步可撤销**。

**产品形态：默认离线，可选自带 key**（依据见[决策记录](决策记录.md)）。

- 默认走离线：不联网、不花钱、断网照样能演（答辩现场网络不可靠）
- 想用真模型：由**使用者填自己的 key**，谁的 key 花谁的钱。
  key 只存在使用者的本机，**绝不写进工程文件**，也绝不打进分发的程序里
- 统一接口按 **OpenAI 兼容格式**设计，换厂商只改地址和模型名；
  本地模型（llama.cpp）也是同一个格式
- AI 面板顶部**明写当前用的是哪一种**（"当前：离线" + "填 key 变聪明"）

**这一版不生成"真图片"**：目前的画面是占位色块，素材系统还没做，
AI 生成的图片没有地方显示（见下面「顺带要问的一件事」）。

**验收**：断网状态下，AI 面板的每个功能都能给出合理结果，并且能撤掉。

### 顺带要问的一件事：要不要做素材系统

计划书里「AI 生成素材」要兑现，得先有一个**能显示图片的素材系统**：
把 PNG 导进工程、指定给某个对象。目前数据模型里留着 `asset_id`，
但没有导入界面，画面一律是彩色方块。

这件事本身不大（导入 + 显示 + 顶替色块），但它是**独立的一块**：
做完之后，才轮到"AI 生成一张贴图给它用"。顺序上建议排在 M4-b 之后。

## 扩展位：别的风格怎么加（刻意留的口子，不排期）

**当前定位只做横版动作 / 平台跳跃类**（依据见[决策记录](决策记录.md)）。
下面写清"以后要加别的风格走哪条路"，目的是**不留悬念** —— 也让接手的人知道
哪些地方是刻意留的口子，而不是没想到。

| 想加什么 | 改哪儿 | 现在的状态 |
| --- | --- | --- |
| 新动作 / 新条件（随机位置、跟着某个对象走…） | 只改 `rule_vocabulary.gd` 一个文件：加一条声明，编辑器表单与规则句子自动跟上 | ✅ 已验证过三次（按键下拉、按键动作表、AI 草稿） |
| 新碰撞身份（能踩的、能推的…） | `EntityDef.collision_group` 加一档 + 运行器分层 + 校验器加提醒 | ✅ 加过「地面」这一档 |
| 整套新风格（俯视角、塔防…） | 加一层**模板**：新工程时选模板 = 一套实体 + 一套规则 + 可用的词汇子集；核心不动 | ❌ 未做。但**不需要改核心** —— "实体 + 规则"本来就是数据 |
| 格子类玩法（贪吃蛇、俄罗斯方块…） | 补 `tile_grid` 的实现（数据结构里已经有了，运行时和编辑器还没实现） | ❌ 未做。位置写在这里 |

**纪律**：新增能力只准"加"，不准"改语义"；非改不可时加 `schema_version`
并写自动升级 —— 「地面」那一档漏了升级，用户当场撞上"金币穿过地面"。

## M6 移动端适配 🚧 以横屏平板为主场

**主战场定为横屏平板**（依据见[移动端适配方案讨论](移动端适配方案讨论.md)）：
手机横屏时上下工具栏要吃掉一半高度，画布只能缩到一半；平板只占四分之一。

- ✅ 触摸手势：单指拖拽对象、单指拖空白处平移画布、双指捏合缩放
- ✅ 触屏尺寸：工具栏按钮放大到该有的高度
- ✅ 触屏点选容差：手指比鼠标粗，触屏设备上点选范围额外放宽
- ✅ 平板实机验证（09-20）：画面铺满屏幕、三个屏幕按键都能用、吃金币与扣血正常。
  发现一处极低概率的"跳得特别高"，触发条件未抓到，用户判断暂不修（见决策记录）
- ✅ 安卓打包：可安装的 APK，33.7 MB，ARM64，已签名

**不做**：底部抽屉、收起侧栏、竖屏布局、双指旋转

**验收**：在平板横屏上完整做出并试玩一个原型；
手机能做到"能装、能跑、能玩"，但不承诺关卡编辑体验。
