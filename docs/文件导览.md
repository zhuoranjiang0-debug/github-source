# 文件夹导览

## 先理解一件事：为什么会有这么多文件

一个软件项目像一栋楼。有的文件是**承重墙**，动了会塌；有的是**装修**，随便改；有的是**脚手架**，只在建造时有用，房子交付后就不需要了。

拆成这么多小文件不是为了显得专业，而是因为**一个文件只干一件事，出问题才知道去哪儿找**。全塞进一个大文件里，两千行之后谁也改不动。

下面按"你要不要管它"分四类。

---

## 一、你会天天碰的（4 个）

| 文件 | 干什么用的 |
| --- | --- |
| `开始游戏.bat` | 双击 = 玩示例游戏「跳跃小恐龙」 |
| `打开编辑器.bat` | 主入口；练习工程可在编辑器里打开后试玩 |
| `运行测试.bat` | 双击 = 跑一遍全部自动检查，确认没被改坏 |
| `app/samples/*.ai2d.json` | 内置示例，只读；在编辑器中修改后保存到 `app/projects/` |

`.bat` 就是把命令行包装成"双击即用"。里面写什么你不用管。

## 三、程序本体（知道有这回事就行）

### `app/` 根目录

| 文件 | 干什么用的 |
| --- | --- |
| `project.godot` | Godot 工程的配置文件：窗口多大、用什么渲染器、启动哪个场景 |
| `scenes/boot.tscn` | 启动场景。程序从这里开始跑 |
| `scenes/capture.tscn` | 给开发用的：自动截图。和产品功能无关 |

### `app/samples/` —— 示例工程

| 文件 | 干什么用的 |
| --- | --- |
| `demo-jump.ai2d.json` | 完整的示例游戏「跳跃小恐龙」，280 行 |
| `practice.ai2d.json` | 练习用的极简工程，70 行，给你改着玩 |

**`app/projects/` —— 你自己的作品**

编辑器里按保存，东西存到这里（默认 `my-prototype.ai2d.json`）。
示例目录是只读的：对示例按保存会自动另存过来，不会把示例覆盖掉。

这个目录**不入库**（写进 `.gitignore` 了）：作品是"各人各机"的东西，不是项目源码。
顺带提醒一句：编辑器启动时会**优先打开你上次的作品**，所以里面一旦有文件，
双击 `打开编辑器.bat` 打开的就是它、不是内置示例——想回到示例，把这个文件移走或改名即可。

### `app/src/` —— 源代码

**入口**

| 文件 | 干什么用的 |
| --- | --- |
| `app_main.gd` | 程序的大门：读工程文件、显示分数血量、处理重开 |

**`app/src/core/model/` —— 数据层：游戏文件的"语法规则"**

| 文件 | 对应 JSON 里的哪一块 |
| --- | --- |
| `game_project.gd` | 整个文件（最外层） |
| `project_config.gd` | `config`（画布、重力、背景色） |
| `asset_def.gd` | `assets`（图片、音效） |
| `entity_def.gd` | `entities`（角色、地面、金币长什么样） |
| `placed_entity.gd` | `scenes[].instances`（谁被摆在哪里） |
| `scene_def.gd` | `scenes`（一个关卡） |
| `rule_def.gd` | `rules`（一条逻辑规则） |
| `rule_vocabulary.gd` | **词汇表**：所有事件、条件、动作的清单，还管"怎么念成人话"，700 多行 |

**`app/src/core/` 其他**

| 文件 | 干什么用的 |
| --- | --- |
| `io/project_io.gd` | 读写 `.ai2d.json` 文件，告诉你是哪一行写错了 |
| `validation/project_validator.gd` | 检查工程有没有问题：引用的东西存不存在、标签对不对得上 |

**`app/src/runtime/` —— 运行器：把数据变成能玩的游戏**

| 文件 | 干什么用的 |
| --- | --- |
| `game_runtime.gd` | 总管：搭场景、生成对象、判胜负、切关卡 |
| `actor.gd` | 场景里的每一个对象（玩家、金币、地面） |
| `rule_engine.gd` | **规则引擎**：执行"当……如果……就……" |
| `placeholder_visual.gd` | 没有图片时画的彩色方块 |

**`app/src/editor/` —— 编辑器：让不写 JSON 的人也能创作**

| 文件 | 干什么用的 |
| --- | --- |
| `edit_session.gd` | 编辑会话：维护工程数据、撤销栈、存盘。**不碰界面，可单独测试** |
| `edit_canvas.gd` | 画布：把对象画出来，接住鼠标（选中、拖动、缩放、平移、接收拖放） |
| `editor_screen.gd` | 编辑器主界面：顶栏 + 画布 + 底部素材栏 |
| `inspector_panel.gd` | 右侧属性面板：**这一个**（位置、缩放、颜色、碰撞、自定义数值）和**这一类**（点素材栏进来：名字、标签、颜色、原始大小、碰撞、会不会动）两种模式 |
| `rule_editor.gd` | 逻辑编辑器：规则清单 +「当…如果…就…」表单（控件由词汇表生成） |

**`app/src/dev/`**

| 文件 | 干什么用的 |
| --- | --- |
| `preview_capture.gd` | 开发工具：自动截图，截图存到 `build/preview.png` |

**`app/src/ai/` —— AI 助手（M4）**

| 文件 | 干什么用的 |
| --- | --- |
| `ai_service.gd` | 统一入口：上层只认它，不关心背后是离线还是在线模型 |
| `offline_provider.gd` | **离线生成器**：不联网、不花钱，认句子里的关键词拼草稿。断网演示靠它 |
| `ai_draft.gd` | 一份「草稿」：还没进工程，等人点了「应用」才生效 |

配套的界面在 `editor/ai_panel.gd`（「✨ 帮我做一个」那一页）。

### `app/tests/run_tests.gd`

自动检查脚本，覆盖数据层、编辑器界面、运行器和 AI 助手。最新检查数量见[测试记录](测试清单.md#测试记录)。每次改完代码跑一遍，没问题才敢往下走。

## 四、辅助工具和杂物

| 文件 | 干什么用的 |
| --- | --- |
| `build/preview.png` | 自动截的游戏画面，做 PPT 时能直接用 |
| `.gitignore` | 告诉 git 哪些文件不用存档（比如 160MB 的引擎本身） |
| `.git/` | git 的存档目录。看不懂没关系，别手动删 |
| `*.uid` | Godot 自动生成的小文件，和脚本一一对应，**别删** |

### 关于 `*.uid` 和 `app/.godot/`

这两样看着像垃圾，其实都不是：

- `.uid` 文件是 Godot 给脚本发的稳定“身份证号”，需要随源码入库，不能当缓存删除。
- `app/.godot/` 是引擎的缓存目录，删了下次打开要重新扫描一遍，只会让你等更久。

只有 `.godot/` 缓存被 `.gitignore` 排除；`.uid` 文件已经被 Git 跟踪，应保留。

---

## 一句话总结

**内置示例在 `app/samples/`，自己的作品在 `app/projects/`**——通过编辑器打开示例，保存时会另存为自己的作品。

其他所有文件都是"能读懂这种 JSON 的程序"。就像 Word 文档和 Word 软件的关系：文档是你的，软件是别人写的。
